# مشروع التحكم الصوتي بالروبوت — C#/.NET + Ollama + NodeMCU

هذا المشروع لا يحتاج Python. يتكون من خادم ASP.NET Core (.NET 8) يعمل على كمبيوتر Windows، وواجهة ويب عربية تفتحها من الموبايل، وكود Arduino للـ NodeMCU ESP8266.

## ما الذي يفعله؟

1. تضغط زر الميكروفون في المتصفح وتتكلم بالعربية.
2. يحوّل المتصفح الصوت إلى نص باستخدام Web Speech API، إذا كان المتصفح والجهاز يدعمان ذلك. قد يستخدم Chrome خدمة تعرف على الكلام عبر الإنترنت؛ هذا ليس Google Cloud Speech API ولا يحتاج إلى API key من Google.
3. يرسل الخادم النص إلى Ollama المحلي، باستخدام `qwen3:8b`، لتصنيفه ضمن قائمة نوايا محددة.
4. الخادم لا يسمح للنموذج بإرسال أوامر Serial حرة. يقبل فقط: تحريك المعصم، فتح الكلابة، إغلاقها، وضع البداية، الحالة، الحركة العشوائية، والإيقاف.
5. بشكل افتراضي، تعرض الواجهة الأمر الذي فُهم وزر **نفّذ الأمر على الروبوت**. يمكنك تفعيل التنفيذ التلقائي من الصفحة بعد اختبار المعايرة.
6. يحرّك الـ NodeMCU السيرفو بحركة غير حاجبة، يصدر نغمات تأكيد وحركة وانتهاء، ثم يفصل إشارة السيرفو بعد 300 ms من انتهاء الحركة. كما يصدر نغمة تحرير مميزة عند الفصل.

## التوصيلات المستخدمة

- Wrist Servo signal: `D1` (GPIO5)
- Gripper Servo signal: `D2` (GPIO4)
- KC1206 buzzer signal: `D5` (GPIO14)
- يجب أن يكون أرضي مزود السيرفو وأرضي NodeMCU مشتركين.
- لا تشغّل السيرفوهات من 3.3V في الـ NodeMCU. استخدم مصدر طاقة مناسبًا للسيرفوهات.
- تحقق من جهد وتيار نسخة KC1206 لديك. إذا كان يسحب تيارًا أعلى من قدرة GPIO، استخدم ترانزستور قيادة مناسبًا بدل تشغيله مباشرة من D5.

## المتطلبات

- Windows 10/11.
- .NET 8 SDK: https://dotnet.microsoft.com/download/dotnet/8.0
- Ollama يعمل محليًا، مع الموديل الذي عندك بالفعل: `qwen3:8b`.
- Arduino IDE لرفع الملف `Firmware/RobotVoiceController.ino` إلى NodeMCU ESP8266.
- الموبايل والكمبيوتر على شبكة Wi-Fi المحلية نفسها.

## قبل أول تشغيل: عاير زوايا السيرفو

افتح `appsettings.json` واضبط القيم التالية وفق الحركة الفعلية لذراعك:

```json
"Robot": {
  "SerialBaudRate": 115200,
  "MinAngle": 0,
  "MaxAngle": 180,
  "GripperOpenAngle": 35,
  "GripperClosedAngle": 120,
  "HomeWristAngle": 90,
  "DetachDelayMs": 300,
  "MoveIntervalMs": 12
}
```

`GripperOpenAngle` و`GripperClosedAngle` أمثلة أولية فقط؛ قد تحتاج عكسهما أو تعديلهما حسب تركيب السيرفو والكلابة. ابدأ باختبار السيرفو دون حمل، وأبعد يدك عن نقاط الانحشار. يمكن ضبط `MinAngle` و`MaxAngle` لتقييد الأوامر الصوتية ضمن المجال الآمن ميكانيكيًا. كود Arduino الحالي يقبل أوامر يدوية من 0 إلى 180؛ تقييد المجال الآمن على الخادم لا يغني عن المعايرة الميكانيكية.

## مفتاح الوصول

في `appsettings.json` غيّر القيمة الافتراضية:

```json
"Security": {
  "AccessKey": "change-this-token"
}
```

إلى مفتاح خاص تختاره، ثم أدخل المفتاح نفسه في حقل **مفتاح التحكم** في صفحة الموبايل. القيمة الافتراضية موجودة للتجربة فقط.

**لا تعمل Port Forwarding للمنفذ 5080 في الراوتر ولا تعرض الخادم للإنترنت.** الاتصال مصمم لشبكة محلية موثوقة. عند ظهور طلب من Windows Firewall، اسمح بالاتصال على شبكة Private فقط.

## رفع كود NodeMCU

1. افتح Arduino IDE.
2. افتح `Firmware/RobotVoiceController.ino`.
3. اختر لوحة NodeMCU ESP8266 والـ COM الصحيح.
4. ارفع الكود.
5. أغلق Serial Monitor بعد الرفع؛ لا يمكن للتطبيق وSerial Monitor استخدام المنفذ نفسه في الوقت ذاته.

الكود يحتفظ بالأوامر المتوافقة مع مشروعك: `w 120`, `g 80`, `s`, `A`, `X`.

## تشغيل خادم .NET

1. تأكد أن Ollama يعمل. يمكنك فحص الموديلات من PowerShell:

   ```powershell
   ollama list
   ```

2. شغّل `run.bat` داخل مجلد `RobotVoiceControl`، أو افتح المشروع في Visual Studio وشغّله.
3. أول مرة، سيستعيد `dotnet restore` حزمة `System.IO.Ports` عبر NuGet.
4. اعرف IP الكمبيوتر المتصل بالـ Wi-Fi من الأمر `ipconfig`. خذ IPv4 الخاص بكرت Wi-Fi، مثال توضيحي `192.168.1.20`.
5. على الموبايل المتصل بالشبكة نفسها افتح `http://192.168.1.20:5080`، مع استبدال المثال بعنوان الكمبيوتر الفعلي.
6. أدخل مفتاح التحكم، واضغط **تحديث**، واختر منفذ COM، ثم اضغط **اتصال**.
7. جرّب أولًا حقل الكتابة: «حرّك المعصم إلى 120 درجة». راجع الزاوية والأمر المعروض، ثم اضغط **نفّذ الأمر على الروبوت**.
8. بعد التأكد من الزوايا والصوت والتوصيلات، يمكنك اختيار **تنفيذ تلقائي بعد فهم الأمر**.

عند الحاجة إلى فتح المنفذ في Windows Firewall، يمكنك تشغيل PowerShell كمسؤول واستخدام قاعدة للشبكة الخاصة فقط:

```powershell
New-NetFirewallRule -DisplayName "Robot Voice Control 5080" -Direction Inbound -Protocol TCP -LocalPort 5080 -Action Allow -Profile Private
```

## أوامر صوتية تجريبية

- «حرّك المعصم إلى 120 درجة»
- «افتح الكلابة»
- «اقفل الكلابة»
- «ارجع إلى وضع البداية»
- «اعرض حالة الروبوت»
- «ابدأ الحركة العشوائية»
- «أوقف الحركة العشوائية»

إذا أخطأ التعرف الصوتي في اللهجة المصرية، جرّب تغيير لغة الميكروفون من `العربية — السعودية` إلى `العربية — مصر`. حقل الكتابة يظل متاحًا للاختبار حتى لو كان المتصفح لا يدعم التعرف على الكلام.

## الأعطال الشائعة

- **Ollama غير متاح:** تأكد من تشغيل Ollama وأن `qwen3:8b` يظهر في `ollama list`.
- **لا توجد منافذ COM:** افصل USB وأعد توصيله ثم اضغط تحديث المنافذ. تحقق من Device Manager.
- **المنفذ مشغول:** أغلق Serial Monitor وأي برنامج آخر يستخدم COM.
- **الميكروفون لا يعمل:** جرّب Chrome على Android مع الإنترنت وصلاحية الميكروفون. دعم Web Speech Recognition يختلف حسب المتصفح والجهاز؛ إذا لم يعمل استخدم حقل النص. في هذه النسخة قد تتم معالجة الصوت عبر خدمة المتصفح، وليس محليًا بالكامل.
- **الحركة ليست سلسة:** قيمة `MOVE_INTERVAL_MS` داخل ملف Arduino تساوي 12 ms. رفعها يجعل الحركة أبطأ؛ خفضها يجعل الحركة أسرع لكن قد تكون أقل استقرارًا مع الحمل.
- **الكلابة تتحرك في الاتجاه الخطأ أو تضغط بقوة:** أوقف التنفيذ التلقائي فورًا وعدّل `GripperOpenAngle` و`GripperClosedAngle` واختبر دون حمل.

## حدود النسخة الأولى

- التعرف الصوتي يعتمد على دعم Web Speech API في متصفح الموبايل، وقد يتطلب إنترنت.
- لا يُشغّل Qwen3 على NodeMCU؛ Ollama يعمل على الكمبيوتر.
- الخادم لا ينفّذ أي نية غير مدرجة في قائمة السماح ولا يرسل نص النموذج مباشرة إلى Serial.
- زر `X` يوقف الوضع العشوائي ويوقف هدف الحركة الجاري في البرنامج الثابت؛ لا يُعد بديلًا عن فصل الطاقة في الطوارئ.
